VHDL funny stuff

VHDL FPGA ENSEIRB

Le VHDL est un langage fascinant — et parfois frustrant. Après plusieurs projets à l'ENSEIRB, j'ai accumulé pas mal de découvertes, bizarreries et petites astuces que j'avais envie de documenter. Voici un recueil de trucs que j'aurais aimé savoir plus tôt.

Le piège du signal vs. variable

L'une des premières sources de confusion en VHDL : les signal ne sont mis à jour qu'à la fin du processus, tandis que les variable le sont immédiatement. Ça peut donner des résultats très surprenants quand on mélange les deux dans un même process. 

process(clk)
  variable temp : std_logic_vector(7 downto 0);
begin
  if rising_edge(clk) then
    temp := input_data;     -- mise à jour immédiate
    sig_a <= temp;           -- prend la NOUVELLE valeur de temp
    sig_b <= input_data;     -- identique à sig_a ici
  end if;
end process;

Mais attention : si sig_a était un signal lu ailleurs dans le même process, il garderait son ancienne valeur jusqu'au prochain delta cycle. C'est un classique qui fait perdre des heures en simulation.

Les « latches » involontaires

Oublier un cas dans un if ou un case sans others ? Le synthétiseur vous crée silencieusement un latch. Le code compile, simule, mais le comportement sur FPGA devient imprévisible. La règle d'or : toujours couvrir tous les cas, toujours avoir un others. 

-- DANGER : latch involontaire si sel /= "00" et "01"
process(sel, a, b)
begin
  case sel is
    when "00" => y <= a;
    when "01" => y <= b;
    -- pas de others => latch sur y !
  end case;
end process;

Generate : la méta-programmation du pauvre

L'instruction generate est sous-utilisée. Elle permet de créer des structures répétitives de manière élégante — chaînes de registres, arbres d'additionneurs, bus paramétrables. C'est presque de la méta-programmation. 

gen_regs: for i in 0 to N-1 generate
  reg_i: entity work.my_reg
    port map(
      clk => clk,
      d   => chain(i),
      q   => chain(i+1)
    );
end generate;

Simulation vs. synthèse : deux mondes

Un code peut parfaitement simuler et être totalement non-synthétisable. Les wait for 10 ns, les accès fichiers, les boucles while sans conditions bornées — tout ça passe en simulation mais sera rejeté par le synthétiseur. Toujours garder en tête la distinction entre les deux.

L'astuce du testbench auto-vérifiant

Plutôt que de vérifier visuellement les chronogrammes, on peut écrire des testbenches qui vérifient automatiquement les résultats avec des assert. Ça change la vie quand on a des dizaines de vecteurs de test. 

assert (output = expected)
  report "ERREUR : sortie = " & to_string(output)
       & ", attendu = " & to_string(expected)
  severity error;

Le VHDL a ses défauts, mais une fois qu'on comprend ses subtilités, c'est un outil puissant pour décrire du matériel. Et chaque projet est l'occasion de découvrir un nouveau piège — ou une nouvelle astuce.
